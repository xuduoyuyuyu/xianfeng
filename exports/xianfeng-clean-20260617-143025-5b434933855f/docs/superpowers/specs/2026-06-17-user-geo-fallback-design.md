# 用户注册城市补全设计

日期：2026-06-17

## 目标

解决后台用户管理里 `城市 / 区域` 大量为空的问题。

成功标准：

- 新用户在短信注册/登录后，后台尽量直接看到 `城市 / 区域`
- 老用户后续登录时，空字段可以被补齐
- 已经人工填写过的 `城市 / 区域` 不被覆盖
- 省份信息只保留在后台字段里，不额外暴露给前台用户侧

## 约束

- 不引入新的重型外部依赖
- 不改后台用户管理页交互，只提升默认数据完整度
- 不把手机号归属地当成强事实，只作为 IP 失败时的兜底

## 方案

### 1. 数据来源优先级

注册或登录补全地理信息时，按下面顺序取值：

1. 公网 IP 定位
2. 手机号号段归属地

规则：

- IP 能拿到 `city + region` 时，直接使用 IP 结果
- IP 只拿到部分字段时，只补空字段
- IP 完全失败时，再查手机号归属
- 手机号归属若只能拿到省份，则只写入 `region`

### 2. 生效入口

补全逻辑覆盖两个现有入口：

- `mobileAuth`
- `login`

行为：

- 新用户首次短信登录建号时，创建用户前先尝试补全
- 老用户登录时，仅在 `city` 或 `region` 为空时回填

### 3. 不覆盖人工值

回填逻辑只在字段为空时写入：

- `city` 已有值时，不覆盖
- `region` 已有值时，不覆盖

这样后台运营人员后续手动修改后，系统不会在下一次登录再改回去。

### 4. 前后台展示边界

- 后台继续展示并允许编辑 `城市 / 区域`
- 前台用户侧不新增省份展示逻辑
- 本次不改用户前台资料页结构

## 实现拆分

### Backend

文件：

- `backend/src/controllers/user.ts`

新增或调整：

1. 增加手机号归属兜底函数
   - 输入手机号
   - 输出 `{ city, region }`
2. 把现有 IP 补全逻辑扩展成：
   - 先查 IP
   - 再用手机号补空字段
3. 在 `mobileAuth` 与 `login` 入口统一调用

### Admin

文件：

- `frontend/src/pages/admin/AdminUsersPage.tsx`

无需改动交互。
当前页面本身已经支持展示和编辑 `city / region`，只要后端写入数据即可生效。

## 错误处理

- IP 定位失败：静默降级到手机号兜底
- 手机号归属失败：静默保留空值
- 任一定位失败都不能阻塞注册/登录成功

## 测试

新增后端定向测试，覆盖：

1. IP 成功时优先使用 IP 结果
2. IP 失败时用手机号归属兜底
3. 已有 `city / region` 时不覆盖已有值

## 风险

- 手机号归属地不是实时居住城市，只能作为后台兜底参考
- 若第三方归属接口返回粒度不稳定，可能出现只有省份没有城市的情况；这是可接受的，因为后台可人工修正
