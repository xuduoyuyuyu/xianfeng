# 登录后引导档案冲突确认设计

## 目标

允许未登录用户先填写城市、区域和学段/年级，但授权登录后不得用这份本地填写覆盖账号已有孩子档案。只有用户明确确认时，才把不同的填写内容建立为另一条孩子档案；用户拒绝时丢弃本次填写。

## 当前问题

`saveProfileOnboardingDraft` 当前把引导内容直接写进本地最近使用的孩子，并在检测到 token 后立即 PATCH `/api/users/me` 与 `/api/users/me/xiaowanzi-sync`。如果授权登录恢复了账号已有档案，本地的“最近使用孩子”可能成为更新目标，造成旧档案被覆盖。

根因是引导填写在账号归属未确定前就被当作正式孩子档案，而不是独立的待确认资料。

## 方案

### 1. 匿名填写只保存待确认资料

未登录用户提交引导卡片时，把标准化后的 `city`、`region`、`grade` 保存到独立的本地 pending key。此时不写 `xf_child_profiles`，不修改最近使用孩子，也不调用后端同步接口。

页面仍可临时使用 pending 资料生成个性化查询，使用户提交后当前内容立即重新排序。

### 2. 登录后先读取账号档案

任意成功授权登录入口完成 `setSession` 后，触发统一的 pending reconciliation：

1. GET `/api/users/me/xiaowanzi-sync` 获取账号 `childProfiles`。
2. 将远端档案落入本地正式档案缓存，保留账号已有内容。
3. 比较 pending 的城市、区域、年级与所有远端孩子档案。

比较前对三个字段去除首尾空白；三个字段全部相同才视为同一份基础资料。

### 3. 三种处理结果

- 账号没有孩子档案：直接用 pending 建立首条“孩子”档案并同步。
- 任一已有档案与 pending 三字段完全相同：关联并切换到该档案，清除 pending，不新增、不覆盖、不弹窗。
- 已有档案存在，但没有完全匹配：显示冲突确认弹窗。

冲突确认文案：

- 标题：`发现已有孩子档案`
- 正文：`刚才填写的信息与已有档案不同，是否为另一个孩子建立新档案？`
- 主按钮：`建立新档案`
- 次按钮：`丢弃本次填写`

点击“建立新档案”时追加新档案，不修改任何已有档案。默认称呼从“孩子”开始；若已占用，依次使用“孩子2”“孩子3”。新档案成为当前档案，然后 PATCH `/api/users/me/xiaowanzi-sync`。个人资料中的城市、区域、年级同步为新当前档案的值。

点击“丢弃本次填写”时只删除 pending，保留远端和本地正式档案原样，并使用原当前档案重新排序内容。

关闭确认弹窗等同于暂不决定：pending 保留，下次进入或登录态恢复时再次询问；不自动新增或丢弃。

### 4. 页面刷新

以下结果发生后通知当前承载页清理首屏缓存并重新请求第一页：

- 自动关联完全匹配档案；
- 确认建立新档案；
- 丢弃本次填写并恢复已有当前档案。

等待用户决定期间，继续使用 pending 资料排序，避免提交后页面跳回未个性化顺序。

## 组件与边界

- `utils/profileOnboarding.js`：pending 的保存、读取、比较、命名、确认结果落地与个性化查询选择。
- `components/profile-onboarding`：保留填写卡片，并承载登录后冲突确认状态和两个操作按钮。
- 登录成功回调：只调用统一 reconciliation，不自行合并档案。
- 后端接口与数据模型不变；继续使用现有 `/api/users/me/xiaowanzi-sync` GET/PATCH 和 `/api/users/me` PATCH。

## 失败处理

- 登录后读取远端档案失败：保留 pending，不写正式档案，稍后重试。
- 用户确认新增后的远端同步失败：本地新增档案保留并标记待同步，沿用现有重试语义。
- 重复触发 reconciliation：同一 pending 只能生成一条档案；成功落地时必须先以三字段重新检查现有列表，再清除 pending。

## 验证

自动测试覆盖：

1. 未登录提交只写 pending，不修改已有正式档案。
2. 登录账号无档案时自动建立首条档案。
3. pending 与任一已有档案完全相同时不新增、不覆盖。
4. pending 不同时返回“需要确认”，且确认前不改已有档案。
5. 确认新增后保留全部旧档案，并生成不重复的默认称呼。
6. 丢弃后只清 pending。
7. 关闭确认后 pending 保留，下次再次提示。
8. 保存、关联、新增或丢弃后的当前内容页均重新加载并使用正确档案排序。

小程序静态与回归测试继续覆盖四个主列表、引导组件、登录回调和 AppleDouble 打包守卫。微信开发者工具验证授权登录、已有档案冲突弹窗、两个决策分支及内容重排。
