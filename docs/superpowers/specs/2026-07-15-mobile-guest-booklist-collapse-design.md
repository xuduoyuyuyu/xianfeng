# 移动端嘉宾书单折叠与小程序原生展示设计

## 目标

嘉宾详情的“推荐书目”在移动端默认最多展示 5 条，其余书单折叠；用户可展开全部并再次收起。小程序原生嘉宾详情新增同一模块，并使用与 Web 端一致的真实书单数据和交互。桌面 Web 继续完整展示全部书单。

## 已确认范围

- 手机浏览器中的嘉宾详情页。
- 小程序 `pages/webview/index` 的原生嘉宾详情模式。
- 所有嘉宾统一应用，不只针对魏智渊。
- 只折叠书单卡片，不截断后端返回的数据。
- 默认显示前 5 条；不足 6 条时不显示展开按钮。

## 数据契约

公共嘉宾详情接口 `GET /api/guests/:id` 新增：

```ts
bookLists: string[]
```

后端按当前嘉宾的 `_id` 查询已发布且 `sourceGuestId` 匹配的图书，只选择 `sourceName` 字段，并执行现有真实书单规则：

1. 按中文分号 `；` 和英文分号 `;` 拆分。
2. 清理首尾空白和包裹整段的成对书名号。
3. 丢弃空名称。
4. 以清理后的完整名称精确去重，保留首次出现顺序。

接口返回完整的去重结果，不在后端截成 5 条。这样 Web 和小程序可以展开全部，且不会各自拉取整库图书或复制解析规则。

不增加数据库字段，不迁移或重写生产图书数据。嘉宾列表接口不增加该字段，避免列表页产生额外查询。

## 移动 Web 行为

- `PublicGuestDetail` 增加可选 `bookLists` 字段。
- 嘉宾详情优先使用接口返回的 `bookLists`，不再为推荐书目拉取整库图书。
- 现有“嘉宾著作”仍可沿用当前图书数据路径；若著作来源与推荐书单同名，前端继续排除重复区域。
- 小于桌面断点时默认渲染前 5 条。
- 超过 5 条时，在卡片列表下方显示“展开其余 N 条”；展开后显示全部并将按钮改为“收起”。
- 收起不主动滚动页面，避免页面位置突然跳动。
- 桌面断点及以上始终显示全部书单，不显示折叠按钮。
- 每条书单继续进入携带 `sourceGuestId`、嘉宾名和精确 `sourceName` 的 `/books` 页面。
- 嘉宾切换时展开状态重置为收起。

## 小程序原生行为

- `normalizeExpertDetail` 接收接口的完整 `bookLists`，生成：
  - `bookLists`：完整列表；
  - `visibleBookLists`：默认前 5 条；
  - `bookListsExpanded`：默认 `false`；
  - `hiddenBookListCount`：剩余数量。
- 在原生嘉宾资料与公开内容之后、AI 对话区之前新增“推荐书目”卡片，视觉沿用现有嘉宾详情卡片、序号和右箭头。
- 超过 5 条时显示“展开其余 N 条”；展开和收起只更新当前详情页本地状态，不持久化。
- 点击书单通过小程序现有 WebView 路由打开 `/books`，携带相同的 `sourceGuestId`、嘉宾名和精确 `sourceName`，保证与移动 Web 的筛选结果一致。
- 无书单时不渲染空卡片或占位文案。

## 异常与兼容

- 旧后端未返回 `bookLists` 时，两端按空数组处理，不阻塞嘉宾基础资料。
- 单条及 5 条以内直接完整展示。
- 展开后仍按接口的首次出现顺序展示，序号保持连续。
- 书单查询失败时嘉宾详情仍正常返回；后端记录错误并返回空数组，避免非核心模块拖垮详情页。
- 不改变桌面书单的卡片样式、顺序和链接语义。

## 验证

1. 后端单元测试覆盖：分号拆分、空值、书名号、精确去重、首次出现顺序，以及详情响应包含完整 `bookLists`。
2. Web 测试覆盖：移动端默认 5 条、展开全部、收起、5 条以内无按钮、桌面不折叠、嘉宾切换重置。
3. 小程序静态与逻辑测试覆盖：原生模块存在、默认 5 条、剩余数量、展开/收起，以及书单点击参数。
4. 运行后端目标测试、前端目标测试、前端构建和小程序目标测试。
5. 本地运行环境可用时，分别截图验证手机浏览器和微信开发者工具中的魏智渊详情页。

## 不在本次范围

- 清洗或重写生产图书来源字段。
- 新建书单集合、书单管理后台或书单分页接口。
- 修改桌面 Web 为折叠展示。
- 修改原生阅读首页的筛选体系。
