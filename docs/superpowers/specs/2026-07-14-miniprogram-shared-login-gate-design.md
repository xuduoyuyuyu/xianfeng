# 微信小程序统一未登录登录层设计

日期：2026-07-14

## 目标

微信小程序内所有需要登录的页面与业务动作，在发现本地无登录会话或接口返回 401 时，立即显示统一的全屏微信手机号登录层。页面不再把“未登录”“请先登录”或“登录已过期”作为普通文案错误展示给用户。

登录必须由用户点击 `open-type="getPhoneNumber"` 按钮触发；小程序不尝试绕过微信的用户手势要求自动获取手机号。

## 统一交互

- 登录层覆盖当前业务页面，不新增独立登录路由。
- 登录层显示统一标题、说明和“手机号快捷登录”按钮。
- 登录中禁用重复操作，并显示“正在登录”。
- 用户拒绝手机号授权、`wx.login` 失败或登录接口失败时，错误只显示在登录层内，并允许重试。
- 登录成功后关闭登录层，保留当前页面和导航栈，并执行当前页面登记的恢复动作。
- 恢复动作应重新读取服务端真实状态；不得用登录前缓存伪造成功结果。

## 触发条件

统一登录层只由以下鉴权状态触发：

1. 进入必须登录才能读取数据的页面时，本地没有 `xf_token`。
2. 点击领取、提交、购买、保存、查看个人数据等受保护动作时，本地没有 `xf_token`。
3. 任意原生请求返回 HTTP 401，`request.js` 清除会话并广播登录过期事件。

以下状态不得触发登录层：

- HTTP 402 或明确的 Pro/会员权限不足。
- 积分不足。
- 表单校验失败。
- 网络错误、超时、服务器 5xx 或资源 404。
- 已登录用户的普通业务失败。

## 组件边界

新增共享原生组件 `components/phone-login-gate/`：

- `index.wxml`：全屏登录按钮和登录层文案。
- `index.wxss`：统一遮罩、卡片和按钮样式。
- `index.js`：处理 `getPhoneNumber`、`wx.login`、`POST /api/wechat-mini/login`、`setSession`、`app.setLoginSession` 和 `resolveAuthExpired`。
- `index.json`：组件声明。

组件公开属性：

- `visible: boolean`：是否显示登录层。
- `title: string`：页面可覆盖登录标题，默认“登录后继续”。
- `description: string`：页面可覆盖简短说明。

组件事件：

- `success`：会话已保存，页面应关闭登录层并执行恢复动作。

登录失败由组件内部处理，不向页面传播为普通业务错误。

## 页面接入

接入范围以代码扫描和测试清单为准，至少包括当前已有鉴权分支的原生表面：

- `pages/welfare/index`：加载福利、领取福利；登录成功后重新加载福利列表。
- `pages/xiaowanzi/index`：AI 对话、历史和个人动作；登录成功后恢复小玩子当前状态。
- `pages/pro/index`：订阅/支付入口；登录成功后刷新用户与产品状态，不自动发起支付。
- `pages/worthbuy/index`：提交和个人状态；登录成功后刷新状态，不自动重复提交。
- `pages/webview/index`：需要 `login=1` 的 Web 内容；登录成功后用新会话重建 Web URL。
- `pages/mama-resource-apply/index`：任务和资料管理；登录成功后重新加载当前账号任务状态。
- 原生设置、我的、资料和节目页中的账号/个人数据入口：无会话时打开统一登录层，登录成功后刷新本页登录态。

纯公开浏览页面不因没有 token 自动遮挡；只有其中的受保护动作触发登录层。

## 鉴权事件与恢复

- 保留 `utils/request.js` 当前 401 行为：清除会话并调用 `notifyAuthExpired()`。
- 需要处理异步 401 的页面订阅 `subscribeAuthExpired`，收到事件后显示共享登录层。
- 组件成功保存会话后调用 `resolveAuthExpired()`，避免过期事件持续挂起。
- 页面在 `success` 事件中调用自己的明确恢复函数；组件不猜测页面数据结构或自动重放具有副作用的请求。
- 领取、提交、支付、保存等写操作在登录后不自动重放，用户需再次确认动作，避免重复提交或意外支付。

## 迁移规则

- 删除或停用页面内重复的 `loginWithPhone` 实现和重复登录遮罩，仅保留页面特有的恢复函数。
- 删除把 401 文案写入普通 `message`、`error`、toast 或空状态卡的分支。
- 已经使用透明全屏授权按钮的页面改为共享组件，保持当前页面登录语义。
- 账号设置中明确可见的“登录”按钮仍可保留，但点击后显示同一共享登录层，不再维护另一套登录请求。

## 测试与验收

1. 共享组件测试覆盖手机号授权缺失、`wx.login` 失败、接口失败和登录成功会话保存。
2. `request.js` 401 测试继续证明会话被清除且鉴权事件只广播一次。
3. 每个接入页面的静态或行为测试证明无 token/401 显示共享组件，而不是普通未登录文案。
4. Pro、积分、网络和业务校验测试证明不会误开登录层。
5. 登录成功后，各页面只执行登记的读取型恢复动作；写操作不会自动重放。
6. 微信开发者工具中至少验证福利页、小玩子页、Pro 页和一个个人资料入口；真机验证 `getPhoneNumber` 授权成功与拒绝路径。

## 非目标

- 不新增独立登录页面或改变导航结构。
- 不修改 `/api/wechat-mini/login` 后端协议。
- 不改变邀请配置、Pro 权限、积分、支付或业务校验规则。
- 不把公开页面整体改成登录后可见。
- 不自动重放领取、提交、支付或保存请求。
