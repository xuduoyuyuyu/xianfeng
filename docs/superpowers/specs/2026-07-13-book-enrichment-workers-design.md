# 及阅图书多信源自动补全设计

## 目标

为及阅本地图书建立可恢复、可审计的多信源补全流水线。首次对全库回填，之后每日巡检新增、已更新、质量分低于 75 或已到重试时间的图书。高置信字段自动写入正式 `BookMetadata`，不恢复人工详情审核队列，不覆盖人工确认的非空内容。

## 范围与原则

- 首期使用确定性 worker，不让自由浏览型 LLM agent 批量搜索网页。
- 信源为 Google Books API、Open Library 低频 API/官方数据 dump，以及现有微信读书候选解析。各信源可独立限速和关闭。
- 只有写入 worker 可修改 `BookMetadata`；采集、匹配、仲裁和标签 worker 只产生持久化候选与决策。
- 简介不由 AI 凭空生成；只允许清洗可追溯的来源内容。标签可根据已采纳简介派生，并标记为 `derived`。
- 不保存整页受版权保护内容；只保留必要字段、来源定位、抓取时间和原始值哈希。

## 任务与 Worker 架构

### 持久任务

`BookEnrichmentRun` 表示一次全量或增量批次，记录总数、成功、跳过、失败和耗时。

`BookEnrichmentTask` 表示单本书任务，状态固定为：

- `queued`
- `collecting`
- `resolving`
- `writing`
- `completed`
- `retry_wait`
- `blocked`

同一本书同一时间只允许一条未结束任务。任务保存开始时的图书/详情版本，写入前再次读取最新记录防止竞争覆盖。

### Worker 责任

1. 调度 worker：创建全量或每日增量任务，全量按质量分升序处理。
2. 信源 worker：Google Books、Open Library、微信读书并行输出统一 `FieldCandidate[]`。
3. 仲裁 worker：只做身份判定、规范化、跨源一致性和字段置信度计算，不访问网络。
4. 写入 worker：唯一修改正式详情的组件，写入前重新校验人工保护与字段空值。
5. 标签 worker：在可信简介已采纳后生成 `derived` 标签候选，不修改书目身份字段。

`FieldCandidate` 至少包含：字段名、规范化值、原始值哈希、信源名、来源 URL 或资源 ID、抓取时间、身份匹配依据和字段置信度。

## 身份判定与字段仲裁

### A/B/C 门槛

- A 级：ISBN-13 或 ISBN-10 规范化后精确一致。书目字段置信基线为 `0.95`。
- B 级：无 ISBN 时，书名规范化后精确一致且作者一致，再满足出版社一致或两家独立信源值一致。单源+出版社一致为 `0.90`，两源一致为 `0.92`。
- C 级：只有书名相似、作者缺失，或存在版本、译者、出版社冲突。不自动写入。

任一身份条件未通过时，内容字段不写入。自动写入的字段置信度必须大于等于 `0.90`。

### 字段规则

- ISBN、作者、出版社、出版日期：优先 Google Books 和 Open Library edition 数据。
- 中文封面和中文简介：微信读书可参与仲裁，但必须先通过 A/B 级身份门槛。
- 封面：除置信门槛外，必须请求成功、返回图片类型，且不得为空图、占位图或及阅兜底 Logo。
- 简介：清除 HTML、来源尾注和营销跳转文案后，有效字符数必须不少于 50。
- 标签：仅从已采纳的可信简介派生，保存 `derived` 标记和模型/规则版本。

## 写入与人工保护

- `reviewedAt` 存在时，任何自动任务不得覆盖非空字段，只能补充仍为空的字段。
- 无 `reviewedAt` 的自动详情也默认只补空；只有已识别为占位封面或占位内容的原值可被替换。
- 写入前重读最新 `BookMetadata`，对任务开始后的人工变更让步。重复执行同一决策不得产生额外变更。
- 正式展示字段继续存在 `BookMetadata`。字段级 provenance 单独持久化，包含信源、定位、抓取时间、置信度、A/B 匹配等级、原始值哈希和采纳结果。
- 写入后重算 100 分质量分。达到 75 分任务完成；低于 75 但没有更多可信候选时，以“低分完成”结束并记录缺口，不立即循环采集。

## 调度、限速与失败处理

- 首次全量回填按质量分从低到高创建任务。
- 每日增量巡检只选择新增、被编辑、质量分低于 75，或已到重试时间的图书。
- 每个信源配置独立并发、速率和超时。Google Books API key 从环境变量读取。Open Library 实时 API 仅作低频补充，批量数据优先使用官方 dump。
- 失败分类为限流、网络、无匹配、身份冲突、字段无效和写入竞争。
- 限流/网络错误指数退避；无匹配延迟到后续巡检；身份冲突进入 `blocked`；写入竞争重读后只补仍为空的字段。

## 后台与可观测性

后台“图书质量”展示待处理、运行中、已补全、低分完成、重试中和阻塞数量，支持按质量分、缺失字段、信源和任务状态筛选。

单书时间线展示每个信源的返回、A/B/C 判定、字段采纳/拒绝原因和质量分变化。管理员可重新采集或停止自动补充，但不引入逐条采纳审核。

## 分阶段启用

1. 代码上线后先选 50 本低分图书运行影子批次，只生成候选、仲裁结果和拟写入 diff，不修改正式详情。
2. 抽样确认误匹配为 0，并统计 A/B/C 比例、字段覆盖和信源失败率。
3. 获得明确放行后，开放 50 本自动写入批次，验证后再逐步扩大，最后执行全库回填。
4. 生产部署、影子批次、自动写入和全库回填是独立放行点，不随代码合并自动执行。

## 验证标准

- 匹配：同名不同作者、同书不同译本、ISBN-10/13 等价、出版社/版本冲突。
- 写入：人工非空字段保护、占位封面替换、简介清洗、并发幂等、任务中断恢复。
- 仲裁：跨源一致、信源冲突、低于 0.90 拒绝、C 级不写入。
- 调度：首次质量分升序、每日增量选择、限流退避、阻塞任务不无限重试。
- 验收：影子批次抽样误匹配为 0；每个写入字段都有 provenance；人工非空字段覆盖次数为 0；重复运行不产生额外变更；外部信源故障不影响公开 `/api/books`。
