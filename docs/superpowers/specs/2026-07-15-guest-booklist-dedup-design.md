# 嘉宾真实书单拆分与去重设计

## 目标

嘉宾详情页展示该嘉宾绑定图书所属于的所有真实书单。一本图书可以同时属于多个书单；页面应拆分这些来源、去重展示，并让每张书单卡片只打开该书单对应的图书。

本次以魏智渊页面暴露的问题为验收样本，但规则适用于所有嘉宾。

## 已确认的根因

- 生产图书已经通过 `sourceGuestId` 绑定到魏智渊，并非绑定数据缺失。
- `sourceName` 当前是一个字符串，一本图书属于多个书单时使用中文或英文分号拼接。
- 嘉宾详情页把整段 `sourceName` 当作一个书单名，因此不同组合被展示为不同卡片。
- 图书列表的 `sourceName` 筛选使用整段字符串完全相等；拆分后的真实书单名不能正确筛选组合来源中的图书。
- 现有嘉宾书单卡片没有传递 `sourceName`，不同卡片最终打开相同的嘉宾完整书库。

## 方案

在前端增加一个共享的纯函数工具，作为嘉宾详情页和图书列表页共同的书单来源解析规则。

### 解析规则

1. 接受未知值，非字符串返回空数组。
2. 按中文分号 `；` 和英文分号 `;` 拆分。
3. 清理每段首尾空白。
4. 清理包裹整段的成对中文书名号 `《》`，再清理一次首尾空白。
5. 丢弃空名称。
6. 使用清理后的完整名称作为去重键，保留首次出现顺序。

不按模糊相似度、包含关系或标题语义合并，避免把名称相近但不同的真实书单错误合并。

### 嘉宾详情页

- 仍以 `sourceGuestId` 判断图书是否属于当前嘉宾。
- 对所有绑定图书的 `sourceName` 执行共享解析。
- 将拆分后的书单名跨图书去重，按首次出现顺序展示。
- 不再以某一本图书代表书单，书单卡片使用稳定的规范化书单名作为展示值和 key。
- 若嘉宾著作也带有书单来源，使用相同解析规则排除已经在“嘉宾著作”中出现的书单。
- 仅在去重后仍存在书单时展示“推荐书目”区域。
- 每张卡片跳转到 `/books`，同时携带 `sourceGuestId`、嘉宾名和该卡片的 `sourceName`。

### 图书列表页

- 保留现有嘉宾 ID 过滤。
- 当 URL 带有 `sourceName` 时，解析每册图书的来源列表，并判断其中是否包含目标书单。
- 不再要求数据库中的整段 `sourceName` 与目标书单完全相等。
- 未携带 `sourceName` 的既有入口行为保持不变。

## 数据与模块边界

- 不修改生产图书或嘉宾数据。
- 不增加数据库迁移，不修改后端 API 响应结构。
- 改动限定在 `frontend-web`：共享解析工具、嘉宾详情页、图书列表页和对应测试。
- 魏智渊生产接口只用于只读验收抽样，不执行写入。

## 异常与兼容

- 空 `sourceName` 不生成书单卡片。
- 只有一个书单名的旧数据保持原样。
- 混用中英文分号可以正确拆分。
- 重复分隔符或多余空格不会产生空卡片。
- 不拆分中文顿号、逗号或斜杠，因为这些字符可能属于真实书单标题。

## 验证

1. 工具单元测试先失败再通过：单个来源、多来源、混合分号、空段、书名号、重复名称和非字符串输入。
2. 嘉宾详情页测试：组合来源被拆分并跨图书去重，链接携带具体 `sourceName`，空结果不展示推荐区域。
3. 图书列表页测试：目标书单可以命中组合来源中的图书，不命中相邻但不同名称。
4. 运行相关前端测试和 `npm run build`。
5. 本地页面可用时检查魏智渊移动端：书单卡片无重复，点击后结果只属于所选书单。

## 不在本次范围

- 清洗或重写生产 `sourceName`。
- 新建独立书单集合或书单管理后台。
- 改变图书详情、搜索或小程序原生阅读列表的来源展示规则。
