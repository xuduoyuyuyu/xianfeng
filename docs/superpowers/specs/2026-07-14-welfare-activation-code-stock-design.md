# 福利激活码与库存一致性设计

## 目标

对已导入激活码的福利活动，保证总库存不超过激活码总数，避免出现库存尚未耗尽但已无激活码可分配的状态。

## 规则

- 活动没有激活码时，保留普通库存模式，总库存按管理员输入保存。
- 活动至少有一个激活码时，视为激活码领取模式。
- 激活码模式下，有效范围是 `已领取数 ≤ 总库存 ≤ 激活码总数`。
- 管理员保存的总库存大于激活码总数时，后端自动将总库存压到激活码总数。
- 管理员保存的总库存小于或等于激活码总数时，保留输入值；不删除多余激活码。
- 总库存不得小于已领取数；如果输入更小，保存值自动提高到已领取数。
- 导入激活码后，继续保持现有行为：总库存更新为激活码总数，且不小于已领取数。

## 数据流

### 编辑活动

1. 后端读取活动当前激活码数量和已领取数。
2. 对请求中的 `totalStock` 执行下界和上界约束。
3. 保存校正后的库存，返回激活码统计。
4. 管理端使用响应覆盖当前表单和列表数据，并在发生校正时显示“库存已按激活码数量调整为 N”。

### 创建活动

新活动创建时还没有激活码，因此不校正库存。首次导入激活码时由导入接口将库存同步为激活码总数。

## 取领边界

- 领取接口继续同时检查库存和未绑定激活码。
- 每次成功领取只绑定一个激活码。
- 不修改重复领取的幂等行为，也不自动补写历史活动。

## 测试

- 编辑有 1 个激活码的活动，输入库存 10，最终保存为 1。
- 激活码数量大于库存时，保留较小库存。
- 库存输入小于已领取数时，最终保存为已领取数。
- 无激活码的普通福利可保存任意非负库存。
- 管理端在后端校正库存后显示实际保存值和调整提示。

## 非目标

- 不新增显式的“领取模式”字段。
- 不删除已导入的激活码。
- 不对生产数据执行一次性重写。
