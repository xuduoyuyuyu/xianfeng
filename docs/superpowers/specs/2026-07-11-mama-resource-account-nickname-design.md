# 妈妈好赚账号昵称设计

## 目标

妈妈好赚资料管理中的每个社交媒体账号都必须录入账号昵称。资料总览和账号编辑卡片直接使用该昵称作为账号标题，不再显示“小红书账号 1”或“抖音账号 2”之类的平台序号标题。

## 范围

- 为主小红书账号增加“账号昵称”输入框，并写入现有 `nickname` 字段。
- 保留新增媒体账号已有的“账号昵称”输入框，将其从可选改为必填。
- 保存资料前校验主账号及所有已添加媒体账号的昵称；任一为空时阻止提交并给出明确提示。
- 资料总览和账号编辑卡片中的账号标题优先显示昵称；平台由 Logo 和平台字段表达，不拼入标题。
- 兼容没有昵称的历史数据：只读展示时继续回退到“平台账号 + 序号”，但再次保存时必须补填昵称。

## 数据流

主账号昵称进入申请草稿，与主页链接、粉丝数等字段一起参与草稿恢复。提交时由现有 `buildSubmitMediaAccounts` 路径写入主账号的 `nickname`，后端继续使用已有的媒体账号 schema 和兼容 `socialAccount` 字段，无需迁移数据库。

## 校验与提示

- 主小红书账号昵称为空：提示用户填写小红书账号昵称。
- 新增媒体账号昵称为空：提示用户填写对应账号昵称。
- 校验发生在网络请求之前，不发送不完整资料。

## 验证

- 静态测试先证明主账号输入框、昵称提交映射、总览昵称标题和必填校验尚未实现。
- 实现后运行 `apps/wechat-miniprogram/pages/mama-resource-apply/index.static.test.mjs`。
- 运行 JavaScript 语法检查和 `git diff --check`。
- 若本地微信开发者工具可用，打开资料管理页，验证输入、空值拦截、保存后总览昵称显示及旧数据回退。

## 非目标

- 不修改后台账号昵称编辑能力。
- 不迁移或批量补写历史账号昵称。
- 不改变平台选择、账号审核或妈妈好赚任务流程。
