# 微信小程序受保护操作直接授权设计

日期：2026-07-14

## 目标

小程序公开页面允许未登录浏览。用户首次点击领取、订阅、分析、发送、保存、查看个人资料等受保护操作时，该次点击直接作为 `getPhoneNumber` 用户手势拉起微信底部手机号授权卡片，不再先显示自定义白色登录中间卡。

本设计覆盖并替代 `2026-07-14-miniprogram-shared-login-gate-design.md` 中“鉴权失败后显示可见共享登录层”的交互结论；登录请求、会话保存和鉴权过期广播机制继续复用。

## 全局规则

- 节目、阅读、话题、搜索、福利列表等公开内容不因未登录被遮挡。
- 页面进入或请求返回 401 时不得自动拉起微信手机号授权；代码只把页面状态切换为未登录。
- 每个受保护主操作本身承担授权手势：未登录时使用 `open-type="getPhoneNumber"`，已登录时执行原动作。
- 用户拒绝授权、微信登录失败或接口登录失败时，在当前页面用 toast 或现有动作错误区域提示，不显示自定义登录卡。
- 授权成功后只恢复发起授权的那一个动作，清空待恢复动作，避免后续误触发。
- 公开操作、筛选、搜索、浏览、返回和分享不得触发授权。

## 恢复动作与安全边界

### 可直接继续

- 福利领取：授权成功后提交本次福利领取。
- 小玩子发送：保留当前输入，授权成功后发送本次问题。
- 知物分析：保留当前输入，授权成功后发起本次分析。
- 妈妈好赚：授权成功后恢复用户明确点击的任务领取、资料保存或回填提交。
- 个人资料读取与保存：授权成功后恢复本次读取或保存。

### 只恢复到确认状态

- Pro 订阅或支付：授权成功后刷新用户和商品状态并回到订单确认，不自动创建订单、不自动扣款。
- 其他具有支付、删除或不可逆副作用的操作：授权成功后恢复页面状态，要求用户再次确认。

## 页面范围

- `pages/welfare/index`：沿用直接领取授权实现。
- `pages/pro/index`：订阅按钮直接授权，成功后刷新状态并保留用户选中的方案。
- `pages/worthbuy/index`：分析/提交按钮直接授权并恢复本次分析。
- `pages/xiaowanzi/index`：发送、历史和个人动作在各自按钮直接授权；页面进入不显示登录层。
- `pages/mama-resource-apply/index`：受保护任务和资料操作直接授权；公开介绍可浏览。
- `pages/webview/index`：原生壳上的受保护操作直接授权；纯 `login=1` 页面需要由进入它的原生按钮承接授权，WebView 页面本身不覆盖白色登录卡。
- `pages/mine/index`、`pages/mine/settings/index`、设置模板及节目/阅读/话题/搜索/资料页的个人入口：现有登录按钮继续直接授权，不增加中间层。

## 共享登录边界

`components/phone-login-gate` 的登录请求能力继续作为共享执行器，负责：

- 接收 `getPhoneNumber` 事件。
- 调用 `wx.login` 和 `/api/wechat-mini/login`。
- 保存会话、更新 App 会话并解除鉴权过期状态。
- 向页面发出成功或失败事件。

页面不再把该组件渲染成可见全屏卡片。页面保存一个明确的待恢复动作标识，并在成功事件中消费一次。

## 测试与验收

1. 代码扫描证明不存在可见的共享白色登录层。
2. 每个受保护主按钮在未登录状态具有 `open-type="getPhoneNumber"` 和对应授权事件。
3. 公开浏览按钮不具有 `getPhoneNumber`。
4. 每页测试证明授权成功只恢复当前动作，授权拒绝不执行原动作。
5. Pro/支付测试证明登录成功不会自动创建订单或扣款。
6. 微信开发者工具验证福利、Pro、知物、小玩子、妈妈好赚各一个受保护动作。
7. 真机验证微信底部手机号授权卡片在首次点击直接出现，并验证允许、拒绝和过期会话三条路径。

## 非目标

- 不修改 `/api/wechat-mini/login` 协议。
- 不要求公开页面登录后才能浏览。
- 不自动触发微信授权卡片；授权必须来自用户点击。
- 不改变会员、积分、库存、支付或业务校验规则。
