# 妈妈好赚移动端任务管理设计

## 目标

让移动端网页 `/mama-resources/apply` 与微信小程序 `pages/mama-resource-apply/index` 使用相同的用户状态分流和任务管理能力。已审核通过的用户通过链接进入后，直接看到账号卡和任务列表，不再被固定带到资料提交界面。

## 范围

本次修改移动端 React 页面及其定向测试，复用现有妈妈好赚 API 和类型。后台派单、Excel 导入、短信、微信小程序页面和后端数据模型不在本次范围内。

## 用户状态分流

页面登录后调用 `publicApi.getMyMamaResourceTasks()`，根据返回结果渲染：

1. `profile` 为空：显示现有资料提交与资料编辑界面。
2. `profile.status` 为 `pending`、`needs_info` 或 `rejected`：显示账号状态、运营备注和“资料管理”入口；不显示可接任务列表。
3. `profile.status` 为 `approved`：默认显示账号已通过卡片和任务列表。
4. 未登录：继续显示手机号验证码登录。登录成功后立即重新加载用户档案与任务，而不是停留在空白资料表单。
5. 请求返回未授权：保留登录界面。其他请求错误：显示加载失败与重试入口，不把错误解释成“尚未提交资料”。

## 已通过账号首页

首屏结构与小程序当前任务页一致：

- 顶部账号卡显示“账号已通过”、妈妈好赚图标、用户昵称、可接品类和“资料管理”按钮。
- 下方按接口顺序显示已分配任务和可领取任务。
- 任务卡显示标题、任务类型与结算周期、任务单价、投流补贴、状态、推广人数、剩余名额和“内容已下发”标记。
- 没有任务时显示明确空状态，不回退到资料提交表单。

视觉使用移动端网页现有导航外壳，但卡片层级、信息顺序、圆角、紫色标签和价格强调与小程序保持一致。

## 资料管理

点击“资料管理”进入现有分区式资料维护界面。加载到的 `profile` 会转换为现有 `FormState`，预填个人资料、主小红书账号、额外媒体账号、接单偏好和授权状态。

保存继续使用 `/api/mama-resources/applications`，不改变提交所有权。保存成功后重新加载档案和任务，并按最新状态返回账号首页或审核状态页。

## 任务详情与回填

点击任务卡在同一 React 页面进入任务详情，展示：

- 项目信息、价格、投流补贴、结算周期、发布要求、结算标准和示例图。
- 已下发专属内容时显示“你的专属任务内容”。点击后弹出“资料链接”卡片，显示任务名、“长按可复制：”和可选择的 `contentUrl`；不尝试嵌入打开飞书。
- 可领取任务显示“立即领取”，调用 `claimMamaResourceTask(id)`，成功后刷新当前任务及列表。
- 已分配任务显示完成链接、截图上传和“提交回填”，分别复用现有上传接口与 `submitMamaResourceTaskProof(id, data)`。
- 返回操作回到任务列表，保留已加载账号和任务数据。

## 组件边界

本次保持在 `MamaResourceApplyPage.tsx` 的页面边界内，但将页面内渲染拆成聚焦的本地组件或纯函数：

- 用户档案到表单状态的转换函数。
- 账号状态卡。
- 任务列表与任务卡。
- 任务详情。
- 专属链接弹窗。

这些单元只通过明确的 props 接收数据和回调，不引入新的全局状态，也不修改导航或后端模块边界。

## 数据与错误处理

- 页面只把 `profile: null` 解释为未建档。
- 网络失败、超时和服务错误都保留为错误状态，并提供重试。
- 领取和回填按钮在请求中禁用，避免重复提交。
- 回填成功后使用接口返回任务更新当前详情和列表。
- `contentUrl` 为空时不渲染专属内容入口。
- 图片上传失败时保留已填写的完成链接和当前任务详情。

## 测试与验收

定向测试覆盖：

- 登录后调用 `/mama-resources/me/tasks`。
- `profile: null`、审核中和 `approved` 三类状态的正确分流。
- 已通过账号首页包含资料管理和任务卡关键字段。
- 任务详情、领取、专属链接弹窗和回填接口绑定。
- 加载错误不回退为资料提交。
- 已有资料正确预填到资料管理表单。

实现后运行前端定向测试和 `npm run build`。由于这是可见移动端改动，还需要在本地移动端视口验证账号首页、任务详情和链接弹窗；未完成该视觉验证时不得声称页面已完全验收。
