# 知物微信小程序原生化设计

## 目标

把微信小程序内知物的公开列表、新分析提交、完整详情、个人历史和删除链路全部改为原生页面。Web `WorthBuyPage` 与 `WorthBuyDetailPage` 继续服务浏览器，并作为原生页面的内容、字段和业务行为基准。

## 路由架构

新增两个独立小程序页面：

- `pages/worthbuy/index`：公开列表、分析输入与提交、个人历史、删除、分页和刷新；
- `pages/worthbuy-detail/index`：公开或个人分析详情、完整报告、参考来源、分享和返回列表。

小程序内所有 `/worthbuy` 入口进入原生列表，所有 `/worthbuy/:query` 入口进入原生详情，包括原生设置菜单、站内搜索、知物卡片、分享落地和历史记录。浏览器中的 Web 路由保持不变。

当前 `pages/webview/index` 已有的 `nativeWorthBuyMode` 详情结构迁移到独立详情页并补齐字段。迁移完成后，通用 WebView 页面不再拥有知物详情状态和样式，避免继续扩大多业务详情容器。

## 列表与提交页

原生列表页包含：

- 与 Web 一致的知物标题、说明和输入区域；
- 支持品牌名、商品全名、电商链接和分享文案；
- 公开发布内容列表；
- 当前登录用户的个人历史；
- 仅针对个人记录的删除操作；
- 下拉刷新、分页追加、缓存先显和明确错误状态；
- 防重复提交的分析进度状态；
- 提交成功后直接进入原生详情。

输入解析和失败引导沿用 Web 的真实规则，不在小程序另造一套产品名提取语义。

## 原生详情页

详情页保持 Web 报告的信息结构，按真实数据有条件渲染：

- 标题、总分、是否智商税、价格区间和核心结论；
- 多维评分；
- 优点和注意事项；
- 商业模式与评论分析；
- 关键数据依据；
- 适合与不适合人群；
- 替代方案；
- 综合建议和购买建议；
- 参考来源；
- 分析时间。

字段没有真实内容时省略整个区块，不生成占位文案。参考链接优先使用小程序允许的安全打开方式；不能直接打开时提供复制链接。

## 数据和权限

保留现有后端契约：

- `GET /api/worthbuy/list`：公开内容；
- `GET /api/worthbuy/my`：个人历史；
- `POST /api/worthbuy/submit`：发起新分析；
- `GET /api/worthbuy/:query`：读取公开或有权访问的个人详情；
- `DELETE /api/worthbuy/my/:brand`：删除个人记录。

公开列表可匿名浏览。个人历史、提交和个人详情遵守现有用户身份规则。新分析继续使用 `worthbuy_analysis` 计费能力并扣除 5 点，不绕过 `requirePro`。

登录缺失、登录过期、`PRO_REQUIRED`、点数不足和普通网络错误分别处理：

- 未登录时在当前原生页发起微信手机号授权；
- 登录过期时清理失效会话并重新授权；
- `PRO_REQUIRED` 或点数不足时展示原生订阅/点数提示，并提供进入原生 Pro 页的动作；
- 网络和服务错误显示可重试提示，不误报为付费墙。

## 原生壳与缓存

列表和详情复用现有 `nativeChrome`、`nativeSettings`、手机号登录、字体设置和分享工具。顶部安全区、胶囊位置、设置抽屉和返回语义与其他一级原生页面一致。

知物使用独立短期缓存键保存公开列表、个人历史和最近详情。页面可以先显示缓存再后台刷新，但缓存只属于知物页面，不写入通用 WebView 缓存，也不能让旧用户身份下的个人历史泄漏到新会话。

## 实施阶段

1. 注册原生路由并完成公开列表、分页、缓存和原生顶部栏；
2. 接通手机号授权、输入解析、提交进度、Pro/点数错误、个人历史和删除；
3. 迁移并补齐完整原生详情报告；
4. 收口设置菜单、搜索、卡片、分享和历史的全部知物入口；
5. 删除通用 WebView 中仅由旧知物详情拥有的状态、模板和样式。

每个阶段必须保持可独立测试，不把四条用户链路一次性塞进一个无法验证的大补丁。

## 验收

自动验证：

- 静态契约测试覆盖页面注册、原生路由、完整字段和通用 WebView 去知物化；
- 页面逻辑测试覆盖公开/个人数据归一化、缓存隔离、输入解析、重复提交、删除和错误分流；
- 后端 WorthBuy 测试覆盖公开读取、个人读取、删除、提交、所有权和 Pro 扣点；
- 小程序包结构与 WebView 兼容测试继续通过。

微信开发者工具验证：

- 匿名浏览公开列表和公开详情；
- 手机号登录后读取个人历史；
- 删除个人记录且不影响公开内容；
- 新分析提交成功并进入原生详情；
- 点数不足和 Pro 门槛显示正确；
- 搜索、菜单、卡片和分享均进入正确原生路由。

真机验证：

- 顶部安全区和胶囊不重叠；
- 长报告滚动、返回和分享稳定；
- 参考链接复制可用；
- 网络较慢时缓存、加载和错误状态真实。

测试通过不等于原生化完成；最终完成需要真实 DevTools 路由和真机关键路径证据。微信上传、审核和发布仍属于独立发布门槛。

## 不在范围内

- 不重新设计 Web 知物产品结构；
- 不修改分析提示词、AI 模型或计费价格；
- 不批量改写现有知物数据；
- 不在本工作流中上传或发布微信小程序。
