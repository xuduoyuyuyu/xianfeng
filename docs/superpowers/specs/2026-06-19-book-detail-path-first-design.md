# 图书详情页路径优先设计

日期：2026-06-19

## 目标

把当前 `及阅` 图书详情页从“基础图书资料页”调整为“路径型详情页”。

成功标准：

- 用户点进一本书后，首屏先看到这本书在家长先疯内容系统里的意义，而不是先看到一组资料字段
- 页面能自然串起 `及阅 -> 节目 -> 嘉宾 -> 继续提问`
- 没有增强元数据时，页面仍可完整打开，不出现空白大块或断层
- 桌面端与移动端都保持稳定的信息节奏，不出现首屏过满或卡片挤压

## 当前现状

当前详情页已经具备这些能力：

- 基础书籍信息：书名、作者、出版社、封面
- 增强元数据：评分、评价人数、标签、简介
- 关系字段：推荐人、来源节目
- 数据接口：
  - `GET /api/books/:id`
  - `GET /api/books/:id/metadata`

当前问题：

- 首屏还是“图书资料优先”，没有先回答“为什么推荐这本书”
- 增强元数据与来源关系是平铺展示，没有形成阅读路径
- 移动端如果继续堆资料字段，首屏很容易变紧

## 约束

- 不改动现有图书详情路由结构，继续使用 `/reading/:id`
- 不新增必须依赖的新外部图书数据源
- 不要求本轮把所有图书补齐完整详情，只基于现有字段设计稳定的降级路径
- 不把本页做成电商型售卖详情页，重点始终是内容理解路径

## 页面方案

### 1. 首屏改为路径优先

桌面端使用 `40 / 60` 双栏：

- 左栏：书封
- 右栏：
  - 来源标签：`来自及阅`
  - 书名
  - 作者 / 出版社 / 评分摘要
  - 路径标题：`这本书为什么会出现在家长先疯`
  - 路径摘要：说明它对应什么家庭问题、适合什么判断场景
  - 主按钮：`继续读这本书`
  - 次按钮：`回到相关书单`

原则：

- 首屏不放长篇“内容简介”
- 首屏的核心是“这本书和用户当下问题有什么关系”

移动端改为单列：

- 先书封
- 再书名和基础信息
- 再路径标题与摘要
- 两个按钮纵向排列

### 2. 第二屏改为“什么时候打开这本书”

这一屏不再重复图书介绍，而是拆成三类理解卡片：

1. 适合解决什么问题
2. 适合什么阶段的人打开
3. 读完最值得带走什么行动线索

桌面端：

- 三列并排卡片

移动端：

- 横向滑动卡片
- 每次露出 1 张完整卡片，并露出下一张边缘

这一层的目标是把“推荐理由”结构化，而不是让用户自己从简介里猜。

### 3. 第三屏放图书资料

这部分是信息归档区，不抢首屏叙事。

布局：

- 左侧：内容简介
- 右侧：作者、出版社、ISBN、评分、评价人数、标签

移动端：

- 简介默认展示前 5 行，超出后显示“展开全部”
- 资料字段做成紧凑信息块

### 4. 第四屏串起家长先疯路径

这一层是本页区别于普通图书详情页的核心。

卡片入口按数据可用性展示：

1. 来源节目
2. 推荐嘉宾
3. 同主题延伸阅读
4. 轻入口：继续提问

跳转关系：

- `来源节目` -> 第一版只展示来源节目名称
- `推荐嘉宾` -> 有 `sourceGuestId` 时跳嘉宾详情页，否则只展示推荐人名称
- `同主题延伸阅读` -> 及阅列表并带筛选条件
- `继续提问` -> 请教一下页或请教一下首页入口

当前 `Book` 只有 `sourceName`，没有 `sourceProgramId`。第一版不根据节目名称拼接节目详情链接，避免生成错误路由。

## 文案口径

### 首屏标题

书名使用原书名，不重新改写。

### 路径标题

固定作为解释性标题，默认使用：

- `这本书为什么会出现在家长先疯`

### 路径摘要

优先级：

1. 如果后端返回人工推荐语，直接使用人工推荐语
2. 如果没有人工推荐语，但有 `sourceName` 或 `recommendedGuest`，前端按模板拼接：
   - `这本书来自《{sourceName}》的阅读线索，适合围绕{topic 或 “家庭教育”}继续往下理解。`
   - 如果没有 `sourceName` 但有 `recommendedGuest`，改为：
   - `这本书由{recommendedGuest}带入家长先疯阅读路径，适合围绕{topic 或 “家庭教育”}继续往下理解。`
3. 如果上述字段都没有，使用通用兜底文案

通用兜底文案：

- `这本书已进入家长先疯阅读路径，详细推荐语仍在补充。`

### 第二屏三张卡的文案口径

不是原始书评，而是“家长使用场景”：

- 困惑场景
- 适用阶段
- 行动线索

### 第三屏简介

优先使用增强元数据里的 `description`，不做人造改写。

## 字段映射

### 已有可直接使用字段

基础书籍：

- `title`
- `author`
- `publisher`
- `coverImage`
- `recommendedGuest`
- `sourceName`
- `topic`
- `grade`
- `categoryLabel`

增强元数据：

- `title`
- `author`
- `publisher`
- `isbn`
- `cover`
- `description`
- `rating`
- `ratingCount`
- `ratingLabel`

### 首屏最低展示要求

只要具备以下任意组合即可打开页面：

- 书名
- 书封或兜底封面
- 作者或出版社至少一个

## 降级策略

### 1. 没有增强元数据

- 首屏照常展示基础书籍信息
- 评分区隐藏
- 简介区显示通用兜底说明
- 路径摘要使用通用兜底文案

### 2. 没有来源节目

- 首屏次按钮改成 `回到书单`
- 第四屏隐藏“来源节目”卡

### 3. 没有推荐嘉宾

- 隐藏嘉宾卡
- 保留延伸阅读与继续提问入口

### 4. 没有简介

- 不留空白块
- 统一显示：
  - `当前只有基础图书信息，详细介绍仍在补充。`

### 5. 没有评分

- 整个评分模块不显示
- 不出现空标签或占位字段

## 实现拆分

### Frontend

文件：

- `frontend/src/pages/BookDetailPage.tsx`

调整内容：

1. 重排首屏布局，从“资料先行”改成“路径先行”
2. 新增第二屏三张场景卡
3. 把当前简介与资料区拆成第三屏
4. 新增第四屏路径入口区
5. 为移动端增加单列与横滑布局

### Backend

本轮不要求新增接口。

继续使用：

- `GET /api/books/:id`
- `GET /api/books/:id/metadata`

不属于本轮范围，但可在后续独立补充的字段：

- 人工推荐语
- 关联节目摘要
- 延伸阅读推荐

但这些不作为本轮上线前置条件。

## 测试与验收

### 功能验收

至少验证：

1. 有增强元数据的书能展示完整路径页
2. 没有增强元数据的书能正常降级
3. 没有来源节目时按钮与入口不出错
4. 移动端首屏不拥挤，第二屏卡片能滑动

### 视觉验收

重点检查：

1. 首屏是否先回答“为什么推荐”
2. 简介是否退到第三层，而不是压回首屏
3. 桌面端与移动端是否都没有大空白和大拥挤同时存在的问题

## 风险

- 现有后端只提供图书元数据，不提供专门的“推荐理由”字段，因此首屏路径摘要第一版仍然要依赖前端拼接或通用兜底
- 如果来源节目和推荐嘉宾字段缺失率高，第四屏路径价值会变弱
- 当前图书增强元数据覆盖仍是样本级，不是全量，因此必须把降级体验当成正式能力来设计
