# 小程序基础档案引导与内容个性化排序设计

日期：2026-07-15
状态：待用户复核

## 目标

为第一次打开小程序且基础资料不完整的用户展示资料引导弹窗，收集城市、区域和孩子学段/年级。资料同时写入个人资料和孩子档案，并用于节目、及阅、学习资料、请教四个小程序主列表的优先排序。

## 范围

本期包含：

- 小程序原生资料引导弹窗。
- 未登录用户的本机基础档案保存。
- 登录用户的个人资料与孩子档案同步。
- 节目、及阅、学习资料、请教四个主列表的个性化排序。
- 保存后的列表缓存失效与刷新。

本期不包含：

- 搜索结果排序。
- 详情页推荐排序。
- 后台内容列表排序。
- 新增画像字段或新的独立画像数据模型。
- 生产数据迁移、部署或发布。

## 已确认规则

### 引导触发

小程序进入前台后，在任一主 Tab 可展示时检查当前基础档案。城市、区域、年级任一字段为空，就需要展示引导弹窗。

用户关闭弹窗时不写入“永久跳过”状态。同一次前台会话内不因切换 Tab 重复打扰；小程序下一次从后台重新进入前台时再次展示。三个字段填写完整后不再展示，除非用户随后在档案管理中清空其中任一字段。

### 登录边界

未登录用户也显示引导并保存到本机。手机号登录成功后，复用现有账号同步机制把本机孩子档案同步到账号。

引导本身不强制登录，也不触发手机号授权。

### 档案选择

没有孩子档案时，创建一条基础档案：

- 称呼：`孩子`
- 城市：用户所选城市
- 区域：用户所选区域
- 年级：由学段与年级组合成现有档案使用的 `grade` 值

该基础档案允许暂时没有生日。档案管理继续允许用户补充姓名、生日和其他字段。

已有孩子档案时，优先更新 `xiaowanzi_last_child_id_v1` 指向的最近使用孩子；该记录不存在或失效时更新第一条档案，不创建重复档案。

### 双写规则

本机孩子档案继续使用现有字段：

- `city`
- `region`
- `grade`

已登录时，同一次保存还更新用户资料：

- `city`
- `region`
- `childGrade`

孩子档案通过现有 `/api/users/me/xiaowanzi-sync` 同步。个人资料通过现有 `/api/users/me` 更新。不得新增含义重复的画像字段。

如果本机保存成功但远端同步失败，弹窗仍关闭并保留本机结果。后续登录恢复或小程序重新进入时重试同步，不能阻断用户浏览。

## 弹窗交互与视觉

弹窗沿用现有手机号授权卡片的视觉语言，但改为小程序原生表单弹窗：

- 全屏半透明深色遮罩。
- 居中白色圆角卡片。
- 顶部使用现有小玩子形象资产。
- 标题说明完善资料后可优先看到更匹配的内容。
- 城市、区域使用现有档案管理的字段和地区选项逻辑。
- 学段、年级使用现有档案管理的级联选项和五四学制规则。
- 右上角关闭按钮只关闭本次前台会话。
- 主按钮在三个字段完整前不可提交，并给出对应缺失提示。
- 提交过程中防止重复点击。

弹窗不收集手机号、孩子生日或真实姓名。

## 组件与职责

### 小程序全局引导控制器

全局控制器负责：

- 从现有本机孩子档案中选出当前档案。
- 判断三个基础字段是否完整。
- 管理“本次前台会话已关闭”的内存状态。
- 在保存后通知当前主列表刷新。
- 在登录状态恢复后触发待同步档案上传。

控制器不拥有新的持久化画像副本，避免与档案数据产生两个真相来源。

### 原生引导组件

原生组件只负责表单显示、选项联动、校验和提交事件。城市、区域、学段及年级的规范化逻辑应从现有档案管理逻辑复用或提取为共享工具，不复制一份常量后各自演化。

### 个性化请求上下文

四个主列表请求附加规范化后的可选参数：

- `profileCity`
- `profileRegion`
- `profileGrade`

这些参数只参与普通主列表排序。搜索请求、详情请求和后台请求不附加这些参数。

### 后端匹配排序

四类列表在应用原有可见性、发布状态和筛选条件后、分页前计算匹配分。评分优先级固定为：

1. 区域精确匹配。
2. 城市精确匹配。
3. 年级精确匹配。
4. 学段匹配。

每类内容只使用自身已经存在的结构化字段、标签、分类和可检索文本来判断匹配，不修改内容记录，也不生成推测性标签。无法从真实内容字段确认匹配时记零分。

排序键为“匹配分降序 + 原排序键”。因此：

- 匹配内容优先展示。
- 不匹配内容仍然保留。
- 同分内容保持当前业务顺序。
- 没有画像参数时返回结果必须与当前顺序一致。
- 分页必须在匹配排序后执行，避免只重排第一页或翻页重复。

## 缓存与刷新

列表缓存键必须包含规范化后的城市、区域和年级，或在画像变化时使旧缓存失效。提交成功后清除节目、及阅、学习资料、请教四类旧列表缓存，并刷新当前可见列表。

其他缓存不得被顺带清理。

## 数据与隐私边界

- 未登录资料只保存在小程序本机现有孩子档案存储中。
- 登录后才写入账号资料与远端孩子档案同步状态。
- 列表请求只发送城市、区域和年级，不发送孩子姓名、生日或其他档案内容。
- 不记录用户关闭弹窗的永久标记。
- 不进行生产数据迁移或批量回填。

## 错误处理

- 本机写入失败：保留弹窗并显示保存失败，允许重试。
- 个人资料或档案远端同步失败：保留本机成功状态，记录待重试，不阻断浏览。
- 个性化参数无效：后端忽略无效值并使用原排序，不能让列表请求失败。
- 排序字段缺失：该内容按零匹配分处理，不隐藏、不伪造字段。
- 列表刷新失败：保留保存成功结果与当前已有内容，按页面现有重试方式处理。

## 验收标准

### 引导与保存

- 无档案用户首次进入会看到弹窗。
- 关闭后当前前台会话不再弹，下一次进入前台重新弹。
- 任一字段缺失时仍满足再次弹出条件。
- 三个字段完整后不再弹。
- 无档案提交后创建称呼为“孩子”的基础档案。
- 有档案提交后更新最近使用孩子，没有最近记录时更新第一条。
- 基础档案即使没有生日也能由引导保存，并可在档案管理继续补全。
- 未登录保存不要求手机号授权。
- 登录后用户资料和远端孩子档案包含相同的城市、区域、年级值。

### 排序

- 四个主列表在有匹配内容时把匹配内容排到更前面。
- 区域、城市、年级、学段按既定优先级参与评分。
- 同分内容维持原业务顺序。
- 没有画像时顺序与改动前一致。
- 翻页不出现因客户端重排造成的重复或遗漏。
- 搜索结果和详情页推荐顺序不变。

### 视觉与运行时

- 微信开发者工具中弹窗遮罩、卡片、选择器、关闭和保存状态正确。
- 小程序重新进入前台的重复弹出规则符合设计。
- 保存后当前主列表立即按新画像刷新。
- 登录、退出登录及账号恢复不会产生重复的“孩子”档案。

## 验证计划

- 小程序静态/单元测试覆盖触发判断、会话关闭、档案选择、基础档案保存、请求参数和缓存失效。
- 后端目标测试覆盖画像参数规范化、评分优先级、稳定排序、分页前排序和无画像兼容。
- 用户路由测试覆盖 `city`、`region`、`childGrade` 更新与孩子档案同步。
- 微信开发者工具运行检查覆盖首次进入、关闭后重新进入、未登录保存、登录后同步及四个主列表刷新。

## 剩余假设与风险

- 内容现有字段对城市、区域和年级的覆盖度不同；本期只基于真实字段匹配，实际提升程度取决于内容元数据质量。
- “重新进入”定义为小程序从后台进入前台，而不是同一次前台会话内切换 Tab。
- 多孩子场景以最近使用孩子作为本期唯一排序画像，不合并多个孩子的字段。
