# 小程序节目详情页真实嘉宾关联设计

## 问题与根因

节目《052.孩子的音乐天赋是如何被“浪费”的？》的线上详情响应同时包含：

- `guestBindings[].guest` 中有先疯智库真实记录“平由植”，ID 为 `6a0271567598bae86f44bad8`。
- 节目旧 `guest` 快照中有无 ID 的“平由植老师”。

小程序 `normalizeProgramGuests()` 将真实关联、`guests` 和旧 `guest` 全部合并，因此把旧快照当成第二位嘉宾。

## 目标

节目存在先疯智库的有效嘉宾关联时，小程序节目详情页只展示这些真实关联，不再展示节目记录中的旧嘉宾快照。

## 范围

- 仅调整小程序原生节目详情页的嘉宾候选来源。
- 不改变后台接口、节目或嘉宾数据模型。
- 不删除或改写线上节目记录的旧 `guest` 字段。
- 不调整网页端、后台管理端或先疯智库列表。

## 来源优先级

1. 从 `guestBindings` 中取出有完整 `guest` 对象且具有 ID 或姓名的有效关联，按 `order` 排序。
2. 只要存在至少一个有效关联，候选集仅使用这些关联，完全忽略顶层 `guests` 和旧 `guest`。
3. 当 `guestBindings` 没有任何有效嘉宾时，才依次使用顶层 `guests` 和旧 `guest` 作为历史数据兼容。
4. 候选集内继续使用现有的 ID/姓名去重、头像回退和文案回退逻辑。

## 异常与回退

- `guestBindings` 不是数组、绑定缺少 `guest` 或嘉宾无 ID 且无姓名时，不视为有效关联。
- 只有无效或已失效绑定时，仍允许旧字段兜底，避免历史节目的嘉宾卡片突然消失。
- 若所有来源都无有效嘉宾，沿用当前的空列表与页面回退行为。

## 验证

- 真实 `guestBindings` 和旧 `guest` 同时存在时，只输出真实关联。
- 存在多个真实绑定时，仍按 `order` 展示并可正常切换。
- 没有有效绑定时，旧 `guest` 仍能兜底展示。
- 无效绑定不会阻止旧字段兜底。
- 运行小程序相关静态测试和完整发版前验证。

## 生产数据边界

本次实施不会清理线上数据库。如后续需要彻底删除历史 `guest` 快照，需要另行盘点影响节目并在生产写入前获得明确批准。
