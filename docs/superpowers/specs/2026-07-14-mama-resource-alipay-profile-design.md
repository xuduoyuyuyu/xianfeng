# 妈妈好赚支付宝收款资料设计

## 目标

妈妈好赚登记资料新增两项资料级收款信息：

- 支付宝账号 `alipayAccount`
- 支付宝验证姓名 `alipayVerifiedName`

两项与自媒体账号的“是否实名认证”相互独立。新提交和补资料时均为必填项，后台、移动 Web 和原生小程序均可查看及修改。

## 数据归属

两项字段直接存放在 `MamaResourceProfile` 顶层，不放进 `socialAccount`、`mediaAccounts` 或任务分配记录。原因是收款资料属于用户的妈妈好赚身份，而不是某个自媒体账号或某次任务。

字段保存前统一去除首尾空格。数据库层保留可选兼容性，使历史资料无需生产迁移即可读取；任何新建或更新申请都必须提交非空的两个字段。

## 接口边界

- 用户申请与资料更新接口接收、校验并保存完整字段。
- 用户本人资料及任务管理接口返回完整字段，用于资料管理回填。
- 管理员列表与详情接口返回字段；列表界面只展示脱敏账号，详情编辑界面展示完整账号和完整验证姓名。
- 公开任务、公开候选内容和与妈妈好赚无关的接口不得新增这两个字段。
- 管理员直接修改历史资料时，两项也必须同时非空，避免继续保存不完整收款信息。

## 三端界面

### 移动 Web

申请和资料管理表单新增两个文本输入框，位于联系方式之后、自媒体账号之前。提交时为空则在本页显示明确校验提示并聚焦首个缺失字段。

### 原生小程序

申请和资料管理表单新增同样的两个输入项，沿用当前页面的数据回填、草稿和提交机制。用户拒绝登录或接口失败时不清空已填写内容。

### 管理后台

资料列表增加一项脱敏收款摘要。支付宝账号按普通账号脱敏：保留前后少量字符，中间用星号替代；过短值只显示星号。资料详情编辑区域展示完整支付宝账号和验证姓名，并允许运营修正。

## 校验与错误处理

- `alipayAccount.trim()` 为空：提示“请填写支付宝账号”。
- `alipayVerifiedName.trim()` 为空：提示“请填写支付宝验证姓名”。
- 后端始终执行同样的非空校验，不能只依赖客户端。
- 不校验账号是手机号还是邮箱，避免阻止合法支付宝登录账号。
- 不自动修改、猜测或格式化验证姓名。
- 历史资料读取时允许字段缺失；进入编辑后提交必须补齐。

## 测试标准

- 模型可以保存并读取两个字段，历史缺失记录仍可读取。
- 申请接口拒绝任意一项为空或只有空格的请求。
- 合法申请保存去除首尾空格后的值。
- 管理员更新资料时执行相同校验。
- 移动 Web 能回填、编辑、提交两项字段，并在缺失时阻止提交。
- 原生小程序能回填、编辑、提交两项字段，并在缺失时阻止提交。
- 后台列表显示脱敏账号，详情编辑显示完整字段。
- 自媒体账号 `realNameVerified` 的现有含义与行为不变。

## 不在本次范围

- 对支付宝账号进行在线真实性验证。
- 自动迁移或批量补齐历史资料。
- 自动发起支付宝转账。
- 将收款信息暴露在公开任务或公开页面。
